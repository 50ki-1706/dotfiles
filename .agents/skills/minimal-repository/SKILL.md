# minimal-repository

## 目的

リポジトリの最小サイズを保つための判断基準を提供します。AI エージェントが変更を加える際に、不要なファイルや重複を追加しないようにします。

## 判断基準

変更を加える前に、次の質問に答えてください。

1. **これは本当に必要か？**
   - 既存のファイルや設定で代替できないか
   - 一時的な用途なら、恒久的な追加を避ける

2. **重複ではないか？**
   - 同じ情報が他の場所に存在しないか
   - 既存の Nix 関数やヘルパーで共通化できないか

3. **最小限の実装か？**
   - 必要十分な範囲を超えていないか
   - 将来的な拡張性を考慮しつつ、現在の要件に過剰でないか

## 具体的なチェックリスト

- [ ] 新しいファイルを追加する前に、既存のファイルで代替できないか確認した
- [ ] 同じ情報を複数の場所に記述していない
- [ ] 測定可能な重複削減になる場合のみ、Nix の `let/in` やヘルパー関数で共通化した
- [ ] ドキュメントの重複を避け、参照リンクを使用した
- [ ] 不要になったファイルや設定を削除した

## 関連する設計思想

- **コンテキスト最小化**: 小さな AGENTS.md をポインターとして配置
- **Nix 関数による重複排除**: mkAgent, mkPermission, readPrompt などのヘルパー
- **Implement by subtraction**: 追加する前に削減を検討
