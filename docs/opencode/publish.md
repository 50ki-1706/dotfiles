# /publish の利用方法

## Summary

`/publish` は現在のエージェントを保ったまま、変更の確認、コミット、プッシュ、PR 作成を進めます。結果には作成した SHA・メッセージ・件数、残存変更、プッシュと PR の状態を報告します。

## Details

Git リポジトリ、固定版 OpenCode 2.1.4 と、現在 Home Manager で管理する `gh`・`git-surgeon` が必要です。直接テストには TypeScript を実行できる Node.js が必要です。Node.js 24.21.0 で検証しています。`gh` の認証はユーザー自身で済ませ、認証情報や認証出力を共有しないでください。公式スキルは Home Manager が固定ソースから OpenCode 用に配置します。管理外の環境では `git-surgeon install-skill --opencode` を使えますが、管理された不変リンクに上書きしないでください。

このリポジトリの設定変更後は、[nix-verify](../../.agents/skills/nix-verify/SKILL.md) の順序に従って `nix fmt`、Home Manager と darwin のビルド、生成物の確認を行います。反映条件と操作は [設定の適用](../home-manager/README.md#設定の適用) を参照してください。プラグインの直接テストは次のコマンドです。

```sh
node --test modules/opencode/plugins/publish/*.test.ts
```

```text
/publish
```

プラグインは公式スキルの出所を確認し、指示をプログラムからプロンプトへ添付します。添付できなければ開始前に停止し、開始済みセッション以外から専用ツールは使えません。操作の `ask` は維持されます。破壊的操作や公開済み履歴の書き換えは行いません。プッシュ前には作業ツリーをクリーンにする必要があります。

非 main では固定版 `git-surgeon` と `pr` の両方が必須です。main は `git-surgeon` のみを必要とします。出所と添付の確認はモデルの記述内容の正しさを保証しません。`pr` の出典と配置は[スキルの管理](../skills/README.md)を参照してください。

PR ブランチでは最新の `origin/main` が HEAD の祖先である必要があります。自動リベースや強制プッシュは行いません。Git の変更一覧に秘密情報を含み得る名前（`.env*`（`.env.example` を除く）、`*.key`、`*.pem`、`id_rsa*`）がある場合は内容を読まず、フロー全体を停止します。`config.env` のような読み取りは既存の確認を維持し、拒否対象と重なる名前は拒否します。

エージェントはプラグインの `publish_inspect` で変更を確認し、未追跡ファイルは安全なパスを明示して対象に含めます。選択した各ハンクを `publish_show` で確認してから `commit_hunks` でコミットします。分割の自動的な正しさは保証しません。既存コミットの分割が必要なら、クリーンな未プッシュの履歴であることを手動で証明したうえで別途対応してください。公開済み履歴は書き換えません。

対象パスの `[` や `*` はパターンではなく文字として扱います。変更ツールの表示制御とは別に、実行時にもリポジトリへの編集権限を確認します。push は対象ブランチだけを送り、タグは送りません。中断や制限超過時は通常の子プロセスとフックも停止しますが、グループを離脱したプロセスや受理済みのリモート操作は対象外です。

PR テンプレートに `Summary`・`Changes`・`Testing` の見出しがある場合、プラグインは例えば `summary_1`・`changes_1`・`testing_1` を必須にした動的スキーマを生成します。エージェントは取得したテンプレート識別値とともに、それらの値を `fields` オブジェクトに入れて `publish_pr` に渡します。実際のキーはテンプレートから決まります。チェックボックスは真偽値、表の空のセルは文字列です。インライン入力は改行を受け付けず、特殊文字をエスケープします。節のテキストにはバッククォート、角括弧、HTML の山括弧や新たな見出し・コードフェンスを入れられません。任意の Markdown の意味を解釈するものではなく、未対応の形式は中断します。

PR 本文には `pr` の方針を使いますが、テンプレートと必須項目が優先です。テンプレートがなければ Summary・Evidence・Merge Danger を使います。実際の変更と検証だけを記載し、未実施や利用できない証拠には理由を添えます。互換性のない図は省略し、証拠を捏造しません。証拠を埋めるためだけに追加の E2E テストや画面収集は行いません。

全体がステージ済みの変更と、独立性を証明できる部分ステージを扱います。競合や未対応のバイナリ・名前変更・シンボリックリンク・ファイルモードの変更は拒否します。インデックスの競合時は既存のステージ状態を確認し、変更を保全してから原因を解消してください。スキルが見つからない場合は管理された配置と設定を確認して再実行します。スキーマや PR テンプレートが変わった場合も `/publish` を再実行します。

コミット後の失敗では自動で巻き戻さず、確認済みの SHA・メッセージ・件数と最後に観測した残存状態を報告します。結果が未確定のコミットはその旨を確認してください。プッシュ成功後に PR 作成が失敗した場合はリモートの SHA と既存 PR を確認し、`/publish` を再実行します。成功時はプッシュ状態と、PR を作成または発見した場合の URL を確認してください。main の公開では PR は作成しません。

分割の意味的な正しさやテスト結果の真偽は自動では証明できません。PR 内容と実際の検証結果を確認してください。境界と状態遷移は [設計](architecture.md) を参照してください。
